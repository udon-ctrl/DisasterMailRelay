# DisasterMailRelay
災害時通信用アプリケーション
# 1. 概要

---

本企画は、**Wi-Fiやモバイル通信が断絶した災害環境下においても、Bluetooth Low Energy（BLE）通信を介してメッセージを中継できるオフラインメールアプリ**「Disaster Mail Relay（仮称）」の開発を目的とする。

React Nativeを基盤とすることで、**iOS / Android両対応の軽量モバイルクライアント**を実現し、ネットワークインフラが破壊された地域内でも、人々が最低限のテキスト通信を継続できる仕組みを提供する。

---

## 2. 背景・課題

- 災害時には基地局や光回線など通信インフラが途絶することが多く、LINEやメール等の既存通信アプリは機能しなくなる。
- 一方で、Bluetoothは半径10〜50m程度で通信可能な近距離無線規格であり、スマートフォン同士が**「中継ノード」として連鎖的にメッセージを伝播**できるポテンシャルを持つ。
- 現行のSNSやメールアプリには「インターネット不要のメッシュ通信」機能が標準搭載されておらず、**自治体・個人ともにオフライン時の通信手段が欠如**している。

---

## 3. 解決策（提案概要）

React Native + BLE技術を用いて、以下の特徴を持つアプリを開発する。

| 機能 | 概要 |
| --- | --- |
| **オフラインメッセージ送信** | Wi-Fi・モバイル通信が不通でも、BLE通信で近隣端末にメッセージを転送 |
| **メッシュ中継** | 受信端末が別の端末へ再送信することで、結果的に“バケツリレー”のように広域伝達 |
| **端末間ID管理** | 匿名化されたユーザーIDで最低限の識別を確保（個人情報は非保持） |
| **ローカルキャッシュDB** | Realm / SQLiteを用い、通信再開時にサーバーへ自動同期可能 |
| **省電力設計** | BLEスキャン・広告の間隔制御により、連続稼働時のバッテリー消費を最小化 |

## 4. 技術概要

### 開発基盤

| 項目 | 技術 |
| --- | --- |
| フロントエンド | React Native (TypeScript構成) |
| 通信モジュール | BLE API（react-native-ble-plx またはネイティブ実装） |
| データ保存 | Realm（オフラインファーストDB） |
| 状態管理 | Redux Toolkit or Recoil |
| 通信制御 | Kotlin（Android）/ Swift（iOS）でブリッジ実装 |
| ビルド環境 | Metro Bundler + Gradle / Xcode |

### 通信プロトコル概要

- メッセージをJSON形式でパケット化：

```json
{
  "id": "<uuid>",
  "from": "<device_id>",
  "to": "<target_id>",
  "body": "<text>",
  "timestamp": "<iso8601>",
  "ttl": 5   // 残り中継回数
}
```

- BLE Advertisingを利用して送信。
- 受信端末は `ttl` を1減らし、未到達の宛先を確認して再送。
- 各端末は受信履歴を保持し、重複受信を回避。

## 5. 運用シナリオ

1. **災害発生直後**
    
    通信障害によりモバイルネットワークが不通。
    
    アプリを起動すると自動的に「近隣探索モード」に移行。
    
2. **近距離端末とのリンク確立**
    
    BLEスキャンによって周囲の端末を検出。
    
    送信者 → 受信者A → 受信者B … と段階的にメッセージが伝播。
    
3. **避難所ネットワーク形成**
    
    一定範囲内に端末が多い環境では、自然に「ローカルメッシュ」が形成。
    
    地域単位でメッセージ交換・安否確認が可能。
    
4. **オンライン復帰時**
    
    通信再開を検知した端末がメッセージログをクラウドにアップロードし、他地域とも再同期。

## 6. 想定課題と展望

| 課題 | 対応策 |
| --- | --- |
| BLE通信距離の限界（約30m） | 中継ノード密度を高める。自治体・避難所に固定ノードを設置。 |
| 消費電力 | アイドル時スキャン間隔を自動調整。 |
| セキュリティ | AES暗号化＋UUID匿名化で個人情報を保護。 |
| プラットフォーム制約 | BLEバックグラウンド動作の制限に対応するため、ネイティブモジュールを強化。 |

将来的には、**LoRaやWi-Fi Directを併用したハイブリッド通信**にも拡張可能。

また、オフラインマップ連携により、**避難経路・安全地点情報の共有**も視野に入れる。

---

## 7. 期待される効果

- 災害直後の「連絡手段ゼロ状態」を大幅に緩和
- 自治体・ボランティア間の連携強化
- 通信インフラ復旧前に「地域ネットワーク」を形成し、安否確認を迅速化

## 9. まとめ

「Disaster Mail Relay」は、**通信インフラに依存しない災害時の命綱アプリ**を目指す。

React Nativeを活用することでクロスプラットフォーム開発を効率化し、

BLEによる近距離メッシュ通信を基盤に、**誰もが持つスマートフォンを“臨時通信ノード”化**することで、

オフライン環境下においても希望のメッセージを届ける社会基盤を構築する。
